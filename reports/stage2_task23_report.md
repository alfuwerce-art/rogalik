# Отчёт задачи 2.3 — утверждение D9 (профиль B) и первый пиксельный проход ворот

> **TASK:** Этап 2, задача 2.3 — зафиксировать решение владельца D16 (пиксельные константы), сделать профиль B основным, выполнить первый пиксельный проход технической зоны-«ворот» на сетке 24 px.
> **STATUS: `PASS`** (технически, все проверки выполнены). Этап 2 остаётся `IN_PROGRESS`; окончательная приёмка — за владельцем.
> Ветка: `stage2-location-prototype`. Дата: 2026-10-25.

## 1. Утверждённые константы (D16)

| Параметр | Значение |
|---|---|
| Размер тайла | **24 px** |
| Высота спрайта героя | **48 px** |
| Масштаб камеры | **zoom 1.0** |
| Направления анимаций | **4** |
| Логическое разрешение | 480×270 |
| Тестовое окно | 960×540 |
| Масштаб арта на экране | 2× |

D16 закрывает отложенный выбор D9. **Не утверждены:** художественное качество спрайтов, оформление первой локации (D10 остаётся в силе), формат атласов, угол камеры, игровые механики.

В коде стандарт применён явно: `PixelProfiles.APPROVED_ID = "b"`, `DEFAULT_ID = APPROVED_ID`, у профилей есть признак `approved`. Обычный запуск (`godot --path game/prototype`) использует профиль B; профили A (16 px / zoom 2) и C (32 px / zoom 1) остались **диагностическими** и печатают предупреждение. Проверено запуском:

```text
CONSTANTS profile=b status=APPROVED tile_px=24 hero_height_px=48 camera_zoom=1.0 directions=4 viewport=480x270 window=960x540 scale=2x source=D16
CONSTANTS profile=a status=DIAGNOSTIC ...  (плюс строка DIAGNOSTIC_PROFILE: не используется для арта)
```

## 2. Первый пиксельный проход ворот

Кадры: **[до](stage2_2_3_gate_before.png)** · **[после](stage2_2_3_gate_after.png)** · **[герой под аркой](stage2_2_3_gate_under_arch.png)** · увеличенные фрагменты: [до ×3](stage2_2_3_gate_before_zoom.png) · [после ×3](stage2_2_3_gate_after_zoom.png).

| Что изменено | До | После |
|---|---|---|
| Силуэт | две плоские доски и балка без структуры | столбы с капителями, железными оковами и каменными опорами; балка с накладками на концах и каменный порог — ворота «стоят» на земле |
| Детализация на сетке 24 px | 1–2 px плоских заливок, случайные насечки | резной пояс балки, заклёпки на оковах, продольные волокна досок, подвес и вырез знамени, оберег-знак, мох у основания |
| Знамя | плоский красный прямоугольник | полотнище с V-вырезом, железными подвесами и золотым знаком (не перетягивает внимание) |
| Контраст с героем | светло-серая притолока на уровне головы героя | притолока тёмная с тенью, порог каменный: силуэт героя читается на её фоне |
| Свет | ночная тонировка + 2 тёплых источника | **не менялось** (дефектов не было) |
| Размер и коллизии | 72×48 px, столб 18 px (0.75 тайла), проём 36 px | **не менялись**: та же сетка, те же коллизии столбов, тот же проход |

Источник арта — `tools/stage2_location/make_proxies.py`, функция `build_gate` (тайл 24 px и параметрически 16/32 для диагностики). Статус арта: **`ASSET_DRAFT`** (рабочий ассет первого пиксельного прохода, художественную приёмку не проходил), дизайн-статус — `VISUAL_CANDIDATE` (локация-кандидат по D10), `ASSET_APPROVED` без решения владельца запрещён. Ассет сгенерирован процедурно; в Pixelorama он не дорабатывался.

## 4. Ограничения и что не проверено

1. Ворота — **`ASSET_DRAFT`**, а не утверждённая архитектура локации: первый проход, не финальная полировка (D10 в силе).
2. Спрайт героя остаётся процедурным **`PROXY_TECHNICAL`** и односторонним; четыре направления утверждены для будущих анимаций Этапа 3, полный лист героя в этой задаче не создавался.
3. **Камера в настоящем бою не проверена**: врагов и атак нет до Этапов 3–5. Проверено только, что кадр пиксельно-точен и не размывается.
4. Пиксельная проверка кадров идёт с допуском ±8: мягкое аддитивное свечение факелов даёт внутри блока отклонения меньше этой границы (строгая проверка без света — 0 отклонений, задача 2.1).
5. HUD по-прежнему занимает нижние 13 % кадра — это ограничение панели, а не констант; вопрос вынесен на Этап 5.
6. Художественная приёмка ворот владельцем не проводилась.
