# Этап 3, задача 3.1 — первый игровой силуэт героя

**TASK:** 3.1 — первый рабочий пиксельный силуэт героя 48 px, четыре направления, минимальный `idle`, выравнивание опорной точки, исходник Pixelorama `.pxo` + PNG-экспорт, интеграция в существующую сцену Godot и проверка смены направлений в реальном запуске.

**STATUS:** **`PASS` (технические проверки)** / **`NEEDS_REVIEW` (художественная приёмка владельцем)**
Готовность ассета: **`ASSET_DRAFT`**. `ASSET_APPROVED` агентом не ставится.

## 1. Что сделано

1. Нарисован силуэт героя 48 px (кадр 32×48) в четырёх направлениях: `down`, `up`, `left`, `right`.
2. Минимальный `idle`: по два кадра на направление (вдох — голова и плечи опускаются на 1 px), стопы и штаны неподвижны.
3. Опорная точка: у всех 8 кадров нижняя граница `y=48`, центр стоп в паре кадров одного направления совпадает; геометрия кадра постоянна, поэтому герой не «прыгает» при смене кадра.
4. Собран настоящий проект Pixelorama `tools/stage3_hero/source/hero_idle_48.pxo` (8 кадров, теги `idle_down|up|left|right`) и **экспортирован самим Pixelorama CLI** в `game/prototype/art/sprites/hero_idle_48.png` (256×48, один ряд из 8 кадров).
5. Герой интегрирован в `scenes/location.tscn`: направление выбирается по доминирующей оси движения, `idle` проигрывается в покое, при движении показывается базовый кадр направления (полная анимация `move` — задача 3.2).
6. Проведён один короткий интеграционный запуск Godot с четырьмя кадрами направлений и одним кадром движения.

## 4. Выполненные команды (реальные)

```powershell
# рисунок + сборка .pxo
$py tools\stage3_hero\author_hero.py --out tools\stage3_hero\source --json reports\stage3_hero_build.json
# экспорт через Pixelorama CLI (не «похожий писатель PNG»)
$env:PYTHONPATH="$PWD\tools"
python -m pixel_pipeline.cli export tools\stage3_hero\source\hero_idle_48.pxo --out game\prototype\art\sprites --sheet --name hero_idle_48
# проверки кадров и валидатор пайплайна
python tools\stage3_hero\check_hero_frames.py --sheet game\prototype\art\sprites\hero_idle_48.png --project tools\stage3_hero\source\hero_idle_48.pxo
# импорт и запуски
godot --path game\prototype --headless --import
godot --path game\prototype -- --face=down  --shot=reports\stage3_hero_frame_down.png  --shot-frames=80
godot --path game\prototype -- --face=up    --shot=reports\stage3_hero_frame_up.png    --shot-frames=80
godot --path game\prototype -- --face=left  --shot=reports\stage3_hero_frame_left.png  --shot-frames=80
godot --path game\prototype -- --face=right --shot=reports\stage3_hero_frame_right.png --shot-frames=80
godot --path game\prototype -- --auto=-1,0  --shot=reports\stage3_hero_move_left.png   --shot-frames=200
godot --path game\prototype -- --face=down  --shot=reports\stage3_hero_idle_a.png      --shot-frames=400
# пиксельная чистота кадров
python tools\stage2_location\check_pixel_scale.py reports\stage3_hero_frame_down.png --block 2 --exclude-bottom 88 --tolerance 8
```

(`$py` — Python 3.12.14 со встроенной средой DSH; путь указан в `docs/ROGALIK_DEV_ENVIRONMENT.md`.)

## 6. Что осталось непроверенным / известные дефекты

1. **Художественное качество** силуэта не доказано ни одной проверкой — это решение владельца.
2. Полной анимации `move`, `dodge`, `attack`, `hurt`, `death` **нет** (следующие задачи этапа).
3. Атлас + JSON и контроллер состояний не начаты.
4. Замер draw calls и стабильности FPS отдельным прогоном не выполнялся (см. §5: только показание HUD).
5. Pixelorama GUI не использовался: `.pxo` собран пайплайном, проверен экспортом через CLI.
6. Кадр вдоха имеет 47 видимых строк силуэта (голова ниже на 1 px); геометрия кадра 32×48 и опорная точка неизменны — это не нарушение высоты 48 px, но об этом нужно знать при покадровой проверке.
