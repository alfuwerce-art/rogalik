Оба файла — **одна и та же запись**: WebP собран из кадров AVI скриптом `tools/stage2_location/make_clip_webp.py`, кадры не рисовались заново. Это не слайд-шоу: клип записан с работающей игры в Movie Maker-режиме (кадр за кадром, фиксированные 60 fps).

**Что показано (маршрут `--demo`, 6.4 с):**

| Сцена | Отрезок маршрута | Что подтверждает лог запуска |
|---|---|---|
| 1. Движение героя по территории | `approach_from_south` → `yard_strafe_west` | `PLAYER_POS` меняется каждый кадр |
| 2. Подход к воротам с юга | `approach_from_south` (0–1.2 с) | `GATE_ENTERED body=Player` |
| 3. Проход под аркой | конец `approach` + `under_arch_fade` | герой проходит между столбами и упирается в стену: `PLAYER_BLOCKED collider=Obstacles` |
| 4. Прозрачность арки при перекрытии | `under_arch_fade` (1.2–2.0 с) | `OVERHEAD_FADE prop=Gate under=true alpha=…` |
| 5. Столкновение со столбом | `post_collision` (2.0–2.9 с) | `PLAYER_BLOCKED x=479.9 y=58.9 normal=(-1.00,0.00) collider=GatePostRight` |
| 6. Работа камеры | весь маршрут | камера следует за героем, кадр остаётся целочисленным (проверено в 2.1) |

Воспроизведение:

```powershell
# запись клипа (нужен только установленный Godot 4.7.2)
godot --path game/prototype --write-movie reports/stage2_clip.avi --fixed-fps 60 -- --demo
# компактная версия из уже записанного AVI
python tools/stage2_location/make_clip_webp.py reports/stage2_clip.avi reports/stage2_clip.webp
```

**О формате MP4/WebM — честный блокер:** в среде нет `ffmpeg`/`ffprobe` (проверено поиском в `PATH`, `Program Files`, WinGet-пакетах, `%LOCALAPPDATA%\Microsoft\WinGet\Packages`, профиле DSH — не найдено), а сторонние компоненты без разрешения владельца не устанавливаются. Поэтому видео записано встроенным средством Godot (AVI/MJPEG) и продублировано компактным WebP. Это ограничение среды, а не работы. Если нужен именно MP4/WebM — требуется разрешение на установку бесплатного `ffmpeg` (одна команда `winget install Gyan.FFmpeg`), после чего AVI конвертируется без потери качества.

## 4. Законченные системы Этапа 2

- Корневая сцена локации `location.tscn` со слоями: земля → детали пола → коллизии → препятствия → перекрытия → персонажи → атмосфера.
- Модульный тайлсет 24 px, собираемый в рантайме, с физическим слоем TileSet (стены и частокол непроходимы).
- Камера с утверждёнными константами, целочисленной привязкой и компенсацией дробной половины кадра (без размытия и дрожания).
- Техническая зона-«ворота»: пропс с первым пиксельным проходом, коллизии столбов, Area2D-зона, прозрачность перекрытия.
- Прозрачность верхних объектов: арка ворот и крона деревьев.
- Базовый свет: ночная тонировка `CanvasModulate` + два тёплых `PointLight2D` у ворот.
- Технический HUD с активным профилем, константами и FPS.
- Инструменты проверки и записи: `check_pixel_scale.py` (пиксельная сетка), `check_tile_seams.py` (швы тайлов), `make_proxies.py` (ассеты), `demo_driver.gd` (маршрут для клипа), `make_clip_webp.py` (упаковка клипа).

## 6. Известные ограничения

1. **«Камера не прячет бой» — `NOT_VERIFIED`.** Кадр проверен только на технической сцене без противников: врагов, атак и телеграфов нет до Этапов 4–5. Предлагаю владельцу **явно перенести эту проверку на этап реализации боевой системы** и не считать её выполненной по текущей сцене.
2. **HUD закрывает нижние 13 % кадра** (36 из 270 px). Записано как известное ограничение; панель не переделывалась, вопрос — к Этапу 5 (боевой HUD).
3. Ворота — `ASSET_DRAFT` первого прохода, не утверждённая архитектура; локация остаётся кандидатом (D10).
4. Спрайт героя — `PROXY_TECHNICAL`, односторонний; четыре направления утверждены для анимаций Этапа 3.
5. Мягкое свечение факелов: пиксельные проверки кадров со светом идут с допуском ±8 (строгая проверка без света — 0 отклонений).
6. За техническую зону ворот ведёт тупик (стена): это техническая карта, а не выход в другую зону локации.
7. MP4/WebM не записаны: в среде нет энкодера (см. §1).
