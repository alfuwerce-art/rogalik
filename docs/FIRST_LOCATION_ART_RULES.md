# Первая локация — художественные и производственные правила для DeepSeek

> **Обязательные правила работы с первой локацией.** Версия 2026-10-25. Общий стиль игры **УТВЕРЖДЁН:** древнерусская кошмарная готика, стилизованное 3D/2.5D, псевдоизометрическая камера. Конкретная **«Проклятая слобода» — пока предложение**, изображения из `assets/references/locations/first_location/` — кандидаты, не одобренные финальные локации.
>
> См.: [ART_DIRECTION.md](ART_DIRECTION.md), [FIRST_LOCATION_CONCEPT.md](FIRST_LOCATION_CONCEPT.md), [GLOBAL_ASSET_PASSES.md](GLOBAL_ASSET_PASSES.md), [DEEPSEEK_GAME_DEV_RULES.md](DEEPSEEK_GAME_DEV_RULES.md).

## 1. Цель и визуальная идентичность

Нужно создать **одну цельную игровую местность**, а не набор разрозненных красивых картинок: северо-восточнославянское деревянное поселение, частокол, дворы, грязевые тропы, резное каменное строение и лес/болотистая низина. В основе — узнаваемые формы исторической архитектуры, сверху — кошмарное фэнтези: пустые дома, брошенные вещи, разорванные красные полотна, следы старых ритуалов, ночной туман, холодная луна и немного тёплого огня.

**Не делать:** европейский готический замок, футуристические конструкции, техногенные фонари, современные здания, неуместные символы из каждого окна, одинаковые кресты/колокола в каждом пропсе, абсолютно чёрную сцену.

**Не заявлять историческую точность**, если конкретные элементы — авторская стилизация. Религиозные постройки и символы использовать осмысленно, не заменяя атмосферу количеством знаков.

## 2. Три основные зоны — пока кандидаты

| ID | Сцена | Художественный акцент | Боевая функция |
|---|---|---|---|
| L01-A | Разрушенные въездные ворота | Бревенчатая башня, покосившийся частокол, пропитанная дождём дорога | Понятная точка входа, пространство для обучения ходьбе и уклонению |
| L01-B | Деревенская площадь | Колодец, резные срубы, телеги, брошенные лавки, отдалённый свет | Арена для боя с несколькими видами пехоты/лучников |
| L01-C | Белокаменное святилище | Резьба, обветшавшие ступени, двор, тёмный лес позади | Сильный архитектурный акцент и возможный рубеж уровня |

Переход через мостки к затопленному лесу — **отдельный кандидат**, пока не требование. Не назначать финального босса, сюжетную последовательность или размеры комнат без решения владельца.

## 3. Визуальный язык

- **Силуэты:** крыши срубов, брёвна, частокол и башни читаются сверху; белокаменное строение — заметный ориентир. Разная высота кровель/построек, без визуальной каши.
- **Материалы:** влажное/почерневшее дерево, тёмная земля, лужи, резной белый камень, ржавое железо, грубый лён, обрывки окрашенной ткани. Материалы художественно стилизованы.
- **Палитра:** холодные сине-серые сумерки, охристый огонь из окон/факелов, редкие красные акценты. Герой и опасные телеграфы контрастируют с землёй.
- **Свет:** ночной вид из референсов — стартовый кандидат; не делать настолько темно, чтобы игрок искал врагов по пикселям. Настройки освещения оценивать в движке.
- **Атмосфера:** туман в дальних слоях и низинах, дым, ветер, влажные отражения. Эффекты **не закрывают** атаки или силуэты.
- **Камера:** постоянная тестовая псевдоизометрия, ориентир из ART_DIRECTION — наклон порядка 40–50° к горизонту, не окончательно утверждённый числовой параметр.

## 4. Порядок производства — глобальные проходы по ВСЕЙ локации

**L0 — Reference board:** собрать три внутренних кандидата, отметить отличающиеся/повторяющиеся элементы и статус каждого. Уточнить единый перечень архитектурных модулей. Все утверждения новых деталей — отдельно.

**L1 — Массовый greybox всех трёх зон:** простые объёмы срубов/крепости/колодца/святилища, пути, препятствия, высоты и границы. **Запрещено** полностью детализировать одни ворота, пока площадь и святилище пусты.

**L2 — Игровая проверка всего greybox:** герой проходит доступные зоны, камера не прячет бой, коллизии работают, есть место для уклонений, враги не застревают, основные маршруты понятны. Снять кадр/короткий игровой ролик для каждой зоны.

**L3 — Модульные модели для всего набора:** сначала формы всех домовых и оборонительных модулей, потом единый набор UV/материалов. Переиспользовать крыши, балки, стены, заборы, ступени. Только затем — индивидуальные отличия.

**L4 — Общая художественная детализация:** общий проход фактур, отделки, пропсов, троп и растительности по всем зонам. Не доводить один дом до фотореализма, пока вся остальная сцена из серых кубов.

**L5 — Свет, атмосферные эффекты и читаемость:** один согласованный цветовой язык на всю локацию, контроль контраста на реальном масштабе, настройка окклюзии (исчезновение/полупрозрачность объектов между камерой и героем).

**L6 — Оптимизация и приёмка:** проверить производительность на целевом ПК, повторно прогнать перемещение/бой, устранить прерывания обзора, коллизионные ловушки, слишком тяжёлые материалы и чрезмерные VFX. Только после этого финальная художественная проверка владельцем.

**Глобальное правило:** `L1(all) → L2(all) → L3(all) → L4(all) → L5(all) → L6(all)`. Допустимы быстрые локальные тесты одного модуля, чтобы не размножить баги; локальный тест **не** заменяет пакетный GATE.

## 5. Обязательные проверки в каждой зоне

| Что проверить | Как предъявить DeepSeek | Статус |
|---|---|---|
| Роль зоны соответствует брифу | Указание L01-A/B/C и воспроизводимый кадр | PASS / FAIL |
| Проходимость/коллизии | Игровой тест передвижения и уклонения | PASS / FAIL / NOT_VERIFIED |
| Камера и закрывающие элементы | Клип боя возле домов/ворот и перекрывающих крыш | PASS / FAIL / NOT_VERIFIED |
| Читаемость врагов и телеграфов | Кадр с реальной камеры, несколько врагов + атака | PASS / FAIL / NOT_VERIFIED |
| Единство стилистики | Общая сводная сцена трёх зон, сравнение референсов | PASS / NEEDS_REVIEW |
| Производительность | Реальные метрики теста с указанием оборудования/режима | PASS / FAIL / NOT_VERIFIED |
| Источники и лицензии | Список сторонних ассетов с правами использования/публикации | PASS / FAIL / NOT_VERIFIED |

Нельзя заявлять `FINAL_PASS`, если обязательные пункты не проверены. Технический smoke-test после маленькой правки; глобальный GATE — по завершении стадии, не тратить часы на одну и ту же общую проверку после изменения фонаря.

## 6. Связь с концепт-артами

**Мастер-арт и три интерьера посёлка** из папки `assets/references/locations/first_location/` служат ориентирами настроения и архитектурных форм. Они не определяют размеры, точный layout или камеры игрового движка.

Обязательные результаты для приёмки:
1. **Мастер-кадр** в реальном движке со стандартной камерой.
2. **Кадры A/B/C** без эффектов для формы и проходимости.
3. **Кадры A/B/C** с тестовыми персонажами и атаками для читаемости.
4. **Короткая запись игрового перемещения/сражения** через минимум две связанные зоны.
5. **Матрица GATE**, подтверждённые коммиты и неустранённые замечания.

Если оригинальные PNG ещё не загружены в GitHub, явно писать `REFERENCE_FILE_MISSING`; не заменять на случайное изображение или Markdown описание и не объявлять визуальную точность проверенной.

## 7. Правила для самостоятельной работы

- Текущая игровая роль локации — **предложение**, а не повод самостоятельно утверждать поселение стартовым биомом. Пока владелец не одобрил, допускается лишь подготовка концептов и технический `PROXY`.
- Не придумывать утверждённых размеров, числа врагов, сюжетных событий или единственного обязательного маршрута. Временные параметры для прототипа маркировать `TEMPORARY`.
- На каждую стадию выдавать короткий план, перечень файлов, игровые доказательства, результаты проверки и следующий незавершённый этап.
- Если два осмысленных исправления не помогают — сформировать `BLOCKER` по [AI_STUDIO_PLAYBOOK.md](AI_STUDIO_PLAYBOOK.md), не перегенерировать всю деревню с нуля.

## 8. Как понять, что образ первой локации удался

Поселение **узнаваемо как древнерусское**, его проклятость заметна без бесконечного количества хоррор-декораций, все три зоны принадлежат одному миру, игрок чётко видит атаки на привычном масштабе, а производительность подтверждена тестом — не одним красивым рендером.
