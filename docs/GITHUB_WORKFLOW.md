## 3. Защита `main` — выполнено владельцем (D11)

**Статус: настроено владельцем 2026-10-25. Повторная настройка не требуется.** Инструкция ниже сохранена как справка и не является задачей агенту.

В GitHub: **Repository → Settings → Branches → Add branch protection rule** (либо Repository rules / Rulesets, если интерфейс показывает этот путь).

- Branch name pattern: `main`.
- Включить `Require a pull request before merging`.
- Включить `Do not allow bypassing the above settings`, если доступно, чтобы запрет соблюдался и владельцем/администраторами.
- **Не включать обязательное число одобрений (Approvals) без второго уполномоченного ревьюера:** в одиночном личном репозитории автор PR не может утвердить собственный PR как независимый ревьюер.
- `Require status checks` включить **после** настройки и фактического запуска CI; иначе можно заблокировать слияние несуществующей проверкой.
- Не разрешать force pushes и deletions. Требовать разрешения обсуждений по желанию.

После изменения проверить через GitHub UI, что `main` отображается как protected. Не пытаться проводить тест прямым push в `main`. Повторно это не выполняется (D11).
