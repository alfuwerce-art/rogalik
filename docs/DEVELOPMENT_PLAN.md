# Rogalik — единый план разработки (этапы 0–6)

> **Статус: УТВЕРЖДЁН владельцем 2026-10-25 (решение D6).** Это **единственный** источник истины о порядке этапов, зависимостях, результатах и условиях приёмки.
> Читать вместе с [AGENTS.md](../AGENTS.md) (основные правила для агента) и [DECISIONS.md](DECISIONS.md) (журнал решений).
> Движок: **Godot 4.7.2 / GDScript** (D1). Графика: **2D Pixel Art, top-down с небольшим углом** (D2). Требования 3D/2.5D не действуют.

## 0. Порядок этапов

```
Этап 0 → Этап 1 → Этап 2 → Этап 3 → Этап 4 → Этап 5 → Этап 6
правила   фундамент  локация   герой    враги    бой      расширение
```

Этапы выполняются **строго по порядку**. Переход к следующему этапу возможен только при выполнении условия перехода предыдущего. Внутри этапа работа делится на **маленькие законченные задачи** — по одной за раз.

## 2. Сквозные правила (обязательны на всех этапах)

1. **Одна задача — одна целевая проверка.** После изменения проверяется только затронутый риск плюс один короткий smoke-test.
2. **Один этап — одна итоговая приёмка.** Полный набор проверок выполняется на закрытии этапа, а не после каждой мелочи и не на каждом ассете.
3. **Доказательства не переснимаются.** Кадр, клип или метрика, полученные для задачи, переиспользуются в приёмке этапа; повторный прогон ради «ещё одного PASS» запрещён.
4. **`PROXY_TECHNICAL` маркируется всегда.** Отсутствие метки — дефект, а не мелочь. См. [DECISIONS.md](DECISIONS.md) D8.
5. **Нет утверждённого референса — нет визуальной разработки.** Ответ `BLOCKED_NEEDS_REFERENCE`, перечень недостающего, остановка на этой единице ([DEEPSEEK_GAME_DEV_RULES.md](DEEPSEEK_GAME_DEV_RULES.md)).
6. **Объём этапа не расширяется самостоятельно.** Новая подсистема — отдельное решение владельца.
7. **Одна большая подсистема за раз.** Не начинать параллельно локацию, героя и бой.
8. **Сохранность работы.** Рабочая ветка не переключается при незакоммиченных изменениях; каждая законченная задача оканчивается локальным коммитом; untracked-результаты экспериментов сохраняются с меткой, а не удаляются; `reset --hard`, `clean -fdx` и `force` запрещены ([AGENTS.md §2](../AGENTS.md)).
9. **Две неудачные попытки — `BLOCKER`.** Дальше отчёт с точной причиной, а не переписывание заново.
10. **Локально — да, публикация — нет.** `push`, Pull Request и merge запрещены до отдельного решения владельца (D5).

## 3. Что показывает владельцу каждая задача

Минимум: `TASK`, `STATUS` (`PASS` / `FIX_REQUIRED` / `NEEDS_REVIEW` / `BLOCKED` / `NOT_VERIFIED`), изменённые файлы, реальные команды проверки, артефакт (кадр/клип/путь), SHA локального коммита, что осталось неподтверждённым.

Правило неизменно: **план, запись конфигурации и «должно работать» не являются выполненной работой.** Подтверждают только реальный запуск и артефакт.
