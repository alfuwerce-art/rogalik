# Обязательные правила разработки Rogalik для DeepSeek Harness

> Канонический входной документ. Версия 2026-10-25. Это **инструкция будущему агенту**, а не утверждение, что он уже запускает Unity/Unreal. Владелец утверждает канон и финальное качество. Движок окончательно не зафиксирован.

## Приоритет источников

1. Последнее прямое утверждённое решение владельца.
2. `docs/ART_DIRECTION.md` — визуальная основа: древнерусская кошмарная готика, стилизованное 3D/2.5D, псевдоизометрическая игра.
3. `docs/BESTIARY.md` и `docs/BOSS_REFERENCES.md` — состав/роли и утверждённые образы.
4. `docs/SKILLS_AND_BOONS.md` и `docs/WEAPON_REFERENCES.md` — механики и оружие, только по релевантной задаче.
5. `docs/GLOBAL_ASSET_PASSES.md` — **обязательный глобальный порядок всех ассетов**.
6. `docs/CHARACTER_PRODUCTION_PIPELINE.md` — проверка каждой модели/анимации внутри глобального этапа.
7. `docs/FIRST_LOCATION_ART_RULES.md` — обязательные правила для окружения первой локации.
8. `docs/REPOSITORY_STRUCTURE.md` и `docs/CONCEPT_ART_INDEX.md` — папки, исходники, статус файлов.
9. `docs/AI_STUDIO_PLAYBOOK.md` и `docs/AI_HINT_LIBRARY.md` — задачи, подсказки и блокеры.

Разногласия не решать наугад: фиксировать конфликт и запрашивать одно конкретное решение. Утверждённый референс ≠ файл в GitHub ≠ готовый игровой ассет.

## Производственный порядок — НЕ «один персонаж до финала»

**Сначала черновики всего утверждённого состава, потом каждая следующая стадия у всех.**

```text
M0 список ВСЕХ моделей и источников
 → M1 простая геометрия ВСЕХ
 → M2 базовые риги ВСЕХ
 → M3 базовые анимации ВСЕХ
 → M4 интеграционные тесты ВСЕХ
 → M5 улучшение геометрии и материалов ВСЕХ
 → M6 анимационная шлифовка ВСЕХ
 → M7 финальная интеграция и визуальная приёмка
```

Точно так же по всем архитектурным модулям выбранной локации. **Нельзя** доводить одного ратника или один дом до последнего шва, пока остальные ещё серые кубы. Допустим короткий технический пилот на 1–2 единицах для проверки импортов/ригов/движений и неутверждённые proxy-формы, но не финальная полировка.

## Проверки этапов

После каждой стадии нужны: реальные файлы, проверяемая сцена, результаты технических тестов, снимки **с игровой камеры**, видеозапись движений/ударов (для моделей) или прохода/боя (для локации), перечень ошибок, короткий отчёт о состоянии **всего пакета**. Состояния `PASS | FIX_REQUIRED | NEEDS_REVIEW | BLOCKED`, никакого «готово» без проверки.

Ходьба/удары: контакт стоп с землёй, инерция и вес, плавные переходы, читаемые замах/попадание/восстановление. Использовать качественную легальную анимационную основу, retarget и контролируемые процедурные коррекции, а не генерировать все ключевые кадры по догадке. Зверям и уникальным боссам нужны совместимые отдельные риги.

Игровые механики: реальная возможность уклониться, совпадение hitbox с клипом, корректные коллизии, отсутствие блокирующих героя стен и VFX, проверка производительности. Компиляция без ошибок **не равна** художественной приёмке.

## Рабочий цикл

1. Проверить существующие файлы и канон. Назвать одну текущую задачу/стадию и что она должна создать.
2. Выбрать минимальные проверяемые действия и необходимые подсказки из `AI_HINT_LIBRARY.md`.
3. Реализовать в отдельной ветке, сохранив стабильное состояние.
4. Выполнить локальную проверку изменения, затем пакетный GATE при завершении стадии. Не повторять огромный тест после каждого пустяка.
5. Исправить конкретную причину. После двух безрезультатных существенно разных попыток — отчёт `BLOCKER`, а не бесконечные переписывания.
6. Передать владельцу кратко: TASK, STATUS, реальные коммиты, что сделано, тесты, визуальные доказательства, что не подтверждено, что дальше.

## Безопасность и лицензии

Не переписывать утверждённые концепты; не называть кандидатов каноном; не заменять отсутствующий PNG похожей картинкой; не публиковать чужие исходники анимаций/моделей без права на распространение. Не ставить платные продукты без согласования. Не публиковать ключи/токены и не удалять чужие файлы молча.

Игра должна **действительно запускаться**. План, тестовые заглушки, красивые PNG и отчёты сами по себе не составляют готовую игру.
