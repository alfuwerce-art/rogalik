# Rogalik — стандарт GPT-изображений, игровых спрайтов и анимационных кадров

> D24/D26 (01.11.2026), `APPROVED` как схема авторства художественной графики. Утверждённые D16, D20, D22, D23 и стандарт художественной приёмки сохраняются. Эта рабочая GitHub-версия дополняет файл `ROGALIK_SPRITE_ANIMATION_STANDARD.txt`, закреплённый в источниках ChatGPT. **Исходники из ChatGPT передаются DeepSeek только фактически**; автоматической передачи нет.

## 1. Разделение ролей

- **ChatGPT** — единственный генератор/художественный редактор для всех новых персонажей, поз, отдельных художественных кадров анимации, врагов, боссов, оружия, окружения, текстур, тайлов, тайлсетов, UI и VFX. Использовать при редактировании оригинальное изображение/утверждённый визуальный мастер как вход, не один текстовый промпт.
- **DeepSeek** — техническая проверка PNG, подготовка альфы, нарезка/выравнивание, метаданные, `.pxo` из переданных файлов, TileSet/TileMap/атласы/SpriteFrames/AnimationPlayer, Godot-свет и игровые сцены, публикация и тесты. Новые **финальные** художественные изображения Python, SDF, Pixelorama-рисованием и собственными нейрогенераторами **не создавать**. Для механик разрешены `PROXY_TECHNICAL`, не выдаваемые за готовый арт.
- Если картинка художественно ошибочна (внешность, анатомия, ткань, палитра, поза), DeepSeek возвращает в ChatGPT **конкретный визуальный дефект**; техническая обработка не должна «улучшать» художественную форму.

## 2. Гейт и масштаб

- D16: тайл **24 игровых px**, герой высотой **48 игровых px**, **4 направления**, zoom **1.0**, логический экран **480×270**, тестовое окно **960×540**. **48 — высота фигуры, не обязательно размер PNG-холста или ячейки атласа.** 96 px только эксперимент, не утверждённая замена.
- Генерация концептов, новых мастер-кандидатов и **одной** тестовой альтернативной позы/кадра для проверки согласованности разрешены до D22 `ART_PRODUCTION_GATE`. **Серийное производство художественных анимаций только после всех 8 условий D22 и приёмки владельца**. Технические контроллеры могут создаваться на прокси.
- Pixel Art должен соответствовать виду **three-quarter top-down**, «древнерусской кошмарной готике», D25 и единственному [HERO_REFERENCE.md](HERO_REFERENCE.md). Базовый герой без оружия. Внутренняя базовая светотень нейтральная; движение света/динамические тени — Godot (D23).

## 3. Мастер, canvas и pivot

1. **Один визуальный мастер на персонажа:** путь к исходному PNG, SHA-256, статус утверждения, размер игровой фигуры, исходное разрешение генератора, направление, палитра, отличительные элементы. Новые кадры создавать **от изображения мастера**, не независимой перегенерацией всего персонажа.
2. Все кадры **одного клипа и направления** имеют одинаковый canvas W×H и внутренний origin/pivot; мировая логическая точка опоры единая между клипами и направлениями. Размеры canvas разных клипов могут отличаться только с корректным сохранением якорей в сцене/атласе.
3. Для idle опора — неизменная точка контакта с землёй между стопами. Не центрировать кадры по меняющемуся силуэту; не обрезать каждый по непрозрачным пикселям отдельно. Не менять масштаб всего героя для имитации дыхания.
4. Idle: нейтральный исходный кадр + небольшие вариации груди, плеч, волос и ткани; стопы, пояс, общий масштаб, позиция в мире остаются неподвижны. `move/attack/dodge/hurt/death` — отдельные клипы со своим рисунком, но тем же визуальным мастером и согласованной опорой.
5. Отдельный изолированный PNG на каждый кадр предпочтительнее случайного коллажа. Если генератор возвращает лист, DeepSeek технически нарезает **только после проверки границ, последовательности, отсутствия обрезки и совпадения качества**.

## 4. Файлы и технические проверки

Контракт записи: `character_id`, `visual_master_path`, `visual_master_sha256`, `master_status`, `direction_id`, `animation_id`, `gameplay_height_px`, `source_resolution_px`, `canvas_size_px`, `pivot_px`, `fps`, `frame_order`, `frame_paths`, `alpha_policy`, `palette_source`, `reviewer_status`, `godot_scene_path`, `commit_sha`. Фактические W×H, FPS и угол камеры не выдумывать.

- PNG RGBA с настоящей прозрачностью (фон alpha=0), полностью непрозрачные участки alpha=255; полупрозрачность там, где она художественно нужна, проверять отдельно. Следить за ореолами premultiplied alpha.
- Игровые экспорты nearest, без размытого ресайза или дробного масштабирования. Проверять обрезку, невидимые поля, опорную точку, pixel jitter, цветовую/форменную согласованность, бесшовность тайлов и реальную читаемость в Godot.
- Для анимаций: сверить кадры попарно по master/pivot, проверить короткий цикл, переход последнего кадра в первый, силуэт, лицо/повязку/волосы, непрерывность одежды/оружия. Размеры PNG, наличие alpha и импорт — только `TECHNICAL_PASS`, не D20 художественная приёмка.
- Художественный результат: `REFERENCE_FIDELITY_GATE=YES/PARTIAL/NO/NOT_VERIFIED`; `ASSET_APPROVED` ставит только владелец, не агент.
- Генератор ChatGPT **не гарантирует** фиксированные размеры, отсутствие дрейфа, точную alpha, равенство пропорций или бесшовность автоматически. При существенном отклонении кадр отвергается и корректируется **в ChatGPT**, а не силовым глобальным resize.

## 5. Передача и хранение

ChatGPT создаёт файлы и сопровождает их ID/назначением/направлением/кадром. Владелец физически передаёт файлы DeepSeek (или доступным согласованным способом), после чего DeepSeek сохраняет **оригиналы GPT и игровые экспорты раздельно**, сверяет SHA и обновляет `docs/ART_ASSET_ANIMATION_REGISTRY.md` + `docs/progress/PROJECT_STATE.md` + `docs/progress/STAGE_03.md`. После локальной проверки — commit и обычный push в `stage3-hero` с проверкой удалённого SHA; `main` не трогать. Если файл фактически не передан — статус `NOT_RECEIVED` / `BLOCKED`, не `PUSHED`.

**Следующий проверяемый шаг по D24:** GPT-мастер H01 → одна GPT-диагностическая поза для проверки согласованности → реальный Godot-кадр от DeepSeek → визуальная приёмка владельца и D22-гейт → после принятия ограниченные GPT-кадры `idle/move`.

**D25 (01.11.2026) — постоянные признаки H01:** чёрная непрозрачная повязка на глазах, чёрная свободная русская рубаха с золотой вышивкой ворот/манжеты, обычное телосложение, каштановые волосы средней длины, короткая борода, коричневые пояс/штаны/обувь. Использовать только новый [HERO_REFERENCE.md](HERO_REFERENCE.md); старые голый торс и красная повязка отменены.

## 6. D26 — обязательный игровой экспорт в ChatGPT, а не концепт-арт

**Правило по умолчанию:** на любой запрос владельца создать игровую графику GPT **в том же ответе** генерирует изображение, технически подготавливает и проверяет **файл GAME_EXPORT**, затем передаёт ссылку на конкретный PNG. Одного изображения, выведенного инструментом генерации, недостаточно. Концепт-листы, портреты, декоративные фоны, подписи, сравнения и сетки вариантов — только по явной просьбе и отдельно от игрового экспорта. Если PNG не создан / технически не прошёл проверки — `NOT_GAME_READY`.

**H01:** один кадр по умолчанию `H01_idle_down_000.png`, figure-height=48 игровых px по альфа-силуэту, true RGBA, фон alpha=0, без встроенных пола/тени/оружия; one canvas, отступы, measured foot pivot. Не выдумывать заранее W×H и (x,y) pivot. Если после сжатия с большого исходника характерные черты теряются — не отдавать как готовый файл, художественно адаптировать в ChatGPT для 48 px. Единственный референс D25. `idle_down` не означает полный пакет анимации.

**Анимация:** после D22 каждый кадр = отдельный реально существующий PNG; неизменны W×H, pivot, масштаб и опорная точка в одном клипе; обязательны порядок, направление, master SHA и JSON-манифест. Спрайт-лист/GIF не замещает исходные PNG. Тайл: 24 игровых px, проверка швов (если заявлена бесшовность — повторить 2×2). Предмет: RGBA+якорь. VFX: RGBA кадры/слои+параметры без незаказанных декоративных фонов.

**FAIL-CLOSED QA до выдачи:** PNG есть и декодируется, режим RGBA, фон alpha=0, bbox не обрезан, измерен target pixel-height (H01=48), холст/pivot фиксированы, контур и материалы читаемы на игровом масштабе; для нескольких кадров одинаковый canvas и опора. `TECHNICAL_EXPORT_PASS` не означает `ART_APPROVED` и не доказывает запуск Godot; последний подтверждается отдельно `GODOT_PASS`, иначе `GODOT_NOT_TESTED`. Доступные в чате файловые/Python-инструменты используются для технической подготовки и проверки; DeepSeek не должен получать вместо PNG лишь эстетичную большую картинку и обязан проверить импорт уже экспортированных файлов.
