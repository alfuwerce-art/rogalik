# Rogalik — первичная настройка 2D-студии и инструментов DeepSeek Harness

> Статус: **план установки и проверки, не отчёт об уже установленных программах**. Обновлено 2026-10-25.
> Актуальный визуальный стандарт: [PIXEL_ART_STYLE_GUIDE.md](PIXEL_ART_STYLE_GUIDE.md).

## 1. Выбранный стартовый стек

- **Godot 4.7.2 Standard (GDScript)** — основной кандидат движка; 2D-сцены, TileMapLayer, импорт PNG, AnimationPlayer / AnimatedSprite2D, VFX, скрипты, запуск через командную строку. Не ставить .NET/Mono или отдельный .NET SDK без технической необходимости.
- **Pixelorama, стабильный релиз** — бесплатный редактор пиксельной графики, тайлов и покадровой анимации.
- **VS Code** — уже использовавшийся пользователем редактор; проверять доступность, не переустанавливать автоматически.
- **Git + GitHub** — код, документация, ревью, история изменений.
- **DeepSeek Harness Desktop** — уже используемая среда агента; сначала проверить установленную версию, профиль и доступные инструменты, не переустанавливать и не сбрасывать настройки.

Почему так: для 2D Pixel Art автоматизированное создание сцен/PNG/атласов и управление тестами обычно проще, чем 3D-модели с UV/скелетами/ретаргетингом. Качество изображений и анимаций всё равно проверяется по реальной игровой сцене.

Официальные источники:
- https://godotengine.org/download/windows/
- https://github.com/Orama-Interactive/Pixelorama/releases
- https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md
- https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/boot/plugin-manager/README.md

## 2. Первый проход на Windows 11

Открыть обычный PowerShell (права администратора заранее не требуются), проверить наличие WinGet:

```powershell
winget --version
```

Установка стандартной версии Godot (без Mono):

```powershell
winget install --id GodotEngine.GodotEngine --exact --version 4.7.2 --source winget --accept-package-agreements --accept-source-agreements
```

Установка Pixelorama:

```powershell
winget install --id OramaInteractive.Pixelorama --exact --source winget --accept-package-agreements --accept-source-agreements
```

Если WinGet сообщает, что пакет уже установлен, **не удалять его**: сначала проверить версию. Если Pixelorama после WinGet не открывается, использовать проверенный официальный выпуск из GitHub Releases вместо непроверенного инсталлятора. Не запускать удалённые PowerShell-скрипты напрямую через `iex`.

Простой диагностический блок (не выводит токены, конфигурационные файлы или содержимое `.env`):

```powershell
$tools = 'winget','git','godot','pixelorama','code','node','npm','pnpm','dsh'
foreach ($name in $tools) {
    $cmd = Get-Command $name -ErrorAction SilentlyContinue
    if ($cmd) { "$name : FOUND : $($cmd.Source)" }
    else { "$name : NOT_IN_PATH" }
}
$profiles = Join-Path $HOME '.dsh\profiles'
if (Test-Path $profiles) {
    'DSH profile names:'
    Get-ChildItem $profiles -Directory -ErrorAction SilentlyContinue | Select-Object -ExpandProperty Name
} else {
    'DSH profiles directory not found in default home (Desktop may still be installed).'
}
```

`NOT_IN_PATH` — только результат проверки командного интерфейса, а не доказательство отсутствия установленной программы. Для Godot/Pixelorama после WinGet может потребоваться новое окно терминала.

## 3. Сначала аудит DeepSeek Harness, затем плагины

1. Открыть существующий **DeepSeek Harness Desktop**, отметить версию и профиль; не менять профиль ИИ-фрилансера.
2. На странице Plugins и/или доступных инструментов проверить фактическое наличие: файловая система, shell/терминал, git/GitHub, запуск процессов, Plugin Manager, Creator Mode, поддержка MCP.
3. Зафиксировать **фактические названия инструментов, версии и активность**. Название установленного плагина не доказывает доступность tool в текущей сессии.
4. Создать отдельный профиль/пресет **для Rogalik**, если это поддерживается текущей версией. Не смешивать инструменты игры с настройками другого агента.
5. Сначала проверить реальное выполнение безопасного shell/file вызова на тестовой папке, затем Godot CLI и запуск небольшой сцены.
6. Только потом подключать проверенный Godot MCP или небольшой собственный инструмент под нужные задачи.

**Важный момент для Desktop:** его профиль принадлежит приложению; не выполнять вслепую `dsh plugin --profile web` или `dsh plugin --profile desktop` из случайно установленной копии CLI. Официальная документация различает Desktop-встроенную команду и npm-CLI: https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md.

## 4. Планируемые инструменты и расширения

| Инструмент | Приоритет | Стратегия |
|---|---|---|
| Файлы, PowerShell, Git | P0 | Проверить встроенные возможности Harness |
| Godot CLI / editor / headless | P0 | Сначала обычные локальные команды и сцена |
| Проверка PNG/тайлов/спрайт-листов | P1 | Простой Python/CLI-скрипт, затем обёртка MCP при необходимости |
| Godot MCP | P1 | Подключать только проверенную совместимую реализацию и проверить вызов |
| Vision или анализ кадров | P1 | Выяснить, может ли текущая модель видеть изображения; не считать это имеющимся |
| Генератор атласов и валидатор кадров | P2 | Собственные инструменты после требований от прототипа |
| Browser MCP | P3 | Пока не обязателен для локальной разработки игры |
| Автосоздание новых плагинов | P2 | После проверки изоляции, прав и повторяемости установки |

## 5. Может ли агент писать себе плагины?

**Да, технически архитектура DSH допускает создание пользовательских плагинов и подключение их в профиль**. Но правом установки, доступностью Creator Mode, совместимостью и реальным включением нового инструмента управляет текущая сессия и профиль; всё надо проверить на работающей системе.

Правильный цикл нового расширения:
1. Агент фиксирует недостающую функцию и интерфейс нового инструмента.
2. Пишет исходный код в изолированной рабочей ветке/директории.
3. Выполняет тесты отдельно от главного профиля.
4. Проверяет зависимости, источник, права и опасные операции.
5. Только после разрешения владельца устанавливает / активирует в нужном профиле.
6. Проверяет **реальный вызов инструмента в новой/текущей сессии**, описывает способ удаления и сохраняет настройки.

**Не давать агенту безусловное право установки/запуска непроверенного стороннего кода, опасных команд, самостоятельного повышения разрешений или изменения других профилей.**

## 6. Первый проверяемый результат

Прототип: одна 2D top-down сцена с тестовым героем, несколькими тайлами, препятствием и врагом. Минимум: передвижение, столкновения, одно предупреждение атаки, один короткий цикл анимации, снимок игровой камеры.

Порядок: **инструменты установлены → обнаружены агентом → реальный вызов → один запуск игры → первый спрайт → первая сцена**.

После подтверждения установки актуализировать `REPOSITORY_STRUCTURE.md` и заменить оставшиеся 3D-специфичные производственные этапы на 2D-эквиваленты. Не заявлять, что эта работа уже выполнена.
