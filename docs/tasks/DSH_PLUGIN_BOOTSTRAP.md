## Фаза 1 — подключить готовые компоненты

## Фаза 2 — написать свои расширения (последовательно, а не всё сразу)

### 1. `rogalik-env-check` — маленький тестовый Cordis-плагин

Создать локальный плагин с одним инструментом `rogalik_env_check`:
- Безопасно определяет наличие/версии Godot, Pixelorama, Git и рабочую папку Rogalik.
- Только чтение; не трогает токены, `.env` и глобальные системные настройки.
- Использует согласованный API инструментов DSH, документированный в `cordis-plugin-development`.
- Тест: новый инструмент реально виден в сессии, его можно вызвать; он выдаёт подтверждённые версии/пути. Провести также проверку после перезапуска сессии, если доступно.
- Код и тесты хранить в рабочей области проекта; permanent-install только штатным Plugin Manager с отдельным запросом подтверждения.

### 2. `rogalik-pixel-pipeline` — полезный рабочий плагин

Писать **после** проверки Pixelorama CLI и определения формата целевых спрайтов:
- экспорт проектов Pixelorama в PNG / спрайт-листы;
- проверка прозрачности, размеров, одинаковой геометрии кадров, повторяемости тайлов и фактического наличия файлов;
- создание/проверка атласа или метаданных кадров для импорта в Godot, если штатный экспорт не покрывает требование;
- отчёт `PASS/FAIL` с конкретными проблемами и путями артефактов;
- минимальный smoke-test на собственном маленьком тестовом спрайте.

Техническая реализация может использовать Python или Godot CLI, но **добавить зависимость только по необходимости**. Никаких платных внешних генераторов или API без отдельного решения владельца.

### 3. `rogalik-game-qa` — только если готовый Godot MCP чего-то не умеет

Не дублировать его функции. Создать лишь при конкретном пробеле: запуск тестовой сцены, сбор ошибок Godot, проверка FPS/логов, сохранение реального скриншота и короткого отчёта о тесте.

## Фаза 3 — демонстрация результата

В отдельной тестовой Godot-сцене (в репозитории, если он готов к структуре движка; иначе во временном каталоге):
1. Добавить примитивного игрового персонажа, пол, одно препятствие и тестовый 2D-спрайт.
2. Запустить движок и реально проверить движение/коллизию либо минимум импорт/запуск сцены при отсутствии контроллера.
3. Через Pixelorama CLI создать или экспортировать PNG/спрайт-лист, проверить его новым инструментом, импортировать в Godot.
4. Если Godot MCP подключён — вызвать его инструмент для инспекции проекта и, если поддерживается, снять кадр запущенной игры.
5. Отчёт должен включать: пути результатов, команды, версии, краткий реальный лог, имена реально вызванных инструментов, статус каждого `PASS/FAIL/BLOCKED/NOT_VERIFIED`, git-коммиты новых рабочих файлов. Не объявлять художественное качество доказанным автоматическим тестом.

## Границы безопасности и время

- Работать только с Rogalik и выделенными тестовыми каталогами; не менять профиль другого проекта, другие репозитории и чужие настройки.
- **Каждая установка нового внешнего плагина, изменение профильного состояния, выполнение непроверенных build scripts и системная установка зависимостей требуют отдельного подтверждения владельца.** Диагностику и создание файлов в рабочей папке выполнять самостоятельно.
- Не запрашивать `danger-full-access` по умолчанию, не запускать скачанные `*.ps1` через `iex`, не публиковать токены/ключи, не включать серверы на `0.0.0.0`.
- Если после двух содержательно разных попыток возникает один и тот же блокер, прекратить цикл и предоставить конкретную диагностику; не менять движок и не ставить десятки плагинов.
- Отчёт давать после **каждой законченной фазы**, не каждых двух команд. Нужен работающий минимальный результат, а не тонны отчётности.
- Не заявлять автоматическую генерацию красивого пиксель-арта или качество анимации без проверки настоящих игровых кадров.
