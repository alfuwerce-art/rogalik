# `tools/stage1_art` — `PROXY_TECHNICAL`

> **Статус: `PROXY_TECHNICAL`** (D3, D8). Это **не** финальный арт и **не** утверждённый ассет.
> Статус дизайна-источника: `VISUAL_APPROVED` для референса героя ([HERO_REFERENCE.md](../../docs/HERO_REFERENCE.md)).
> Готовность ассета: `PROXY_TECHNICAL`. Художественная приёмка не проводилась.

## Что это

Детерминированный автор пиксельных спрайтов героя на Python/Pillow:

| Файл | Назначение |
|---|---|
| `pixel_canvas.py` | холст 1 px = 1 px: жёсткие края, без сглаживания и субпиксельных координат |
| `hero.py` | лист героя 48×56: `idle / move / dodge / attack / hurt / death` × направления |
| `_preview_closeup.py` | вспомогательный скрипт увеличенного превью |
| `*.png` | превью-кадры для сравнения, не игровые ассеты |

## Чем это не является

- Не финальный спрайт, не ассет для сборки, не доказательство художественного качества.
- Не заменяет утверждённый референс и не является его «улучшенной версией».
- Не отменяет пайплайн: игровой спрайт проходит через Pixelorama (`.pxo`) и `tools/pixel_pipeline`, а не только через этот скрипт.

## Как запускать

```powershell
py tools/stage1_art/hero.py   # перегенерация PNG-превью
```

Результаты проверяются пайплайном (`rogalik_pixel_pipeline check`) на сетку кадров, прозрачность и нижнюю границу; проверка подтверждает геометрию, **не «красоту»**.

## Правила

1. Не выдавать содержимое этого каталога за финальный арт в отчётах и коммитах.
2. Не переносить эти файлы в `game/prototype/art/` как «готовые» без прохождения Pixelorama-пайплайна и отдельной приёмки.
3. Не удалять каталог: он сохранён как подтверждение проделанной работы (D8).
